# Architecture

Status: approved 2026-10-24 and built branch by branch through Phase 3 (TASK.md). The source of truth for module layout (CLAUDE.md).

Tags: **[V]** verified (seen in this repo, or in a clean-room note under [research/](research/)); **[I]** inferred (Apple-platform knowledge not checked against Apple documentation in Phase 1, or reasoning). Design proposals are not claims and carry no tag. Every [I] item about an Apple API should be checked against Apple's documentation when Phase 2 implements it.

Choices marked **(Dn)** are accepted decisions in [DECISIONS.md](DECISIONS.md).

## 1. Principles

1. Productivity first: a module earns its place by making a frequent action faster.
2. Event-driven by default. Every timer is listed in section 9 with an interval and a reason.
3. Private APIs live behind a protocol in `Services/` with a public fallback, so a macOS update turns off one feature instead of crashing the app (CLAUDE.md).
4. One module = one folder = can be switched off with no side effects (no observers, timers or permission prompts while off).

Rules:
- Modules depend on `Services/` protocols, never on each other.
- `Notch/` knows about modules only through the registry (section 3).

## 3. Module protocol and registry

Every feature module implements one protocol, `NotchModule` in `Notch/NotchModule.swift` (with the `CompactSlot` enum). The code is the source of truth; this is a sketch of its shape:

```swift
@MainActor
protocol NotchModule: AnyObject {
    var id: String { get }                       // stable key used by layout and settings storage
    var title: LocalizedStringResource { get }
    var systemImage: String { get }              // SF Symbol for its tab
    var hasCompactView: Bool { get }             // can fill a compact slot at all (default false; Now Playing only)
    var hasCompactContent: Bool { get }          // e.g. Now Playing only while something is playing
    var homeCard: HomeCardSize? { get }          // non-nil: a card on Home instead of a tab (default nil; D42)

    func compactView(slot: CompactSlot) -> AnyView   // left or right of the notch
    func expandedView() -> AnyView
    func settingsView() -> AnyView

    func start()                                 // called only while enabled; begins observing
    func stop()                                  // called when disabled or app quits; safe to call twice
}
```

The protocol does not inherit `Identifiable`; `id` is a plain `String`.

Home cards (D42): a module with a `homeCard` size has no tab. `registry.homeCards` lists the enabled ones in `tabOrder`, and `HomeModule`'s view lays them out in one row with `HomeLayout`. Home reads the registry from the SwiftUI environment; it is the only module that does, and no module depends on another module's type. `moveTab` moves a module among the enabled modules of its own kind, and a module missing from a saved order goes in at its default index.

Why it looks like this (notes for a Swift newcomer):
- `@MainActor`: every module drives UI state, so the compiler guarantees it is only touched on the main thread. Background work happens inside services, which hand results back to the main actor.
- `AnyObject`: modules are long-lived reference types the registry owns. A struct would be copied, and `start()`/`stop()` would act on the wrong copy.
- `AnyView` return types: the registry keeps modules of different types in one array. A protocol with an associated `View` type can't sit in a plain array without type erasure, and `AnyView` is the simplest erasure. Apple documents that changing the wrapped view type destroys and rebuilds the hierarchy [V: https://developer.apple.com/documentation/swiftui/anyview]; no diffing cost is documented. Module view types don't change once placed, so this rebuild doesn't recur [I].
- The enabled flag lives in the registry, not on the module (D21), so there is one source of truth and the notch view redraws when it changes. A disabled module runs no observers, timers or prompts. `start()`/`stop()` are separate from the flag so the registry decides when observers run (for example, stop everything when the screen sleeps).

`ModuleRegistry` (in `Notch/`) owns the module instances in a fixed order, keeps each module's enabled flag in `UserDefaults` (`module.<id>.enabled`, on by default), calls `start()`/`stop()` when the flag changes while it is running, and gives the layout the enabled modules in `tabOrder`, plus the module for each compact slot (D8). The initialiser has a `precondition` that module ids are unique: duplicate ids would share one saved flag and one slot, so a duplicate is a programming error and stops the app. `precondition` is checked in Release builds as well as Debug, unlike `assert` [I: Swift standard library behaviour, not checked against Apple's documentation]. The layout slots (`compactLeftID`, `compactRightID`, `tabOrder`) are set in Settings › Modules and saved in `UserDefaults` (`layout.*`, D34). In `tabOrder` the modules that are on always come first: `setEnabled` moves a module to the boundary, `moveTab` only swaps two modules that are on, and an older saved order is sorted at launch (D36). `compactWings` is the set of slots whose module is enabled and has compact content; `AppDelegate` observes it and passes it to `NotchState.setWings`, which widens the closed shape on those sides only (D28, D36).

What exists today: `AppDelegate` creates one registry holding `HomeModule`, `NowPlayingModule` (built on `ScriptablePlayersSource`; a Home card), `NotesModule`, `FileTrayModule` and `ClipboardModule`, and calls `start()` at launch and `stop()` at quit. When the app is hosting unit tests (`XCTestConfigurationFilePath` is set) it never calls `start()`, so a test run doesn't contact real players. `NowPlayingModule` reads the source's `AsyncStream<NowPlayingInfo?>` in a `Task` that `start()` creates and `stop()` cancels, then clears `info`, and sends playback commands with `send(_:to:)`. `ScriptablePlayersSource` turns the players' distributed notifications and `NSWorkspace` launch and quit into that stream, through the pure `PlayerNotificationParser` and `NowPlayingSelection`, and sends Apple Events through `AppleEventSending` (D22–D24). `NoNowPlayingSource` never yields and sends nothing; it is for tests.

`NotchRootView` shows the selected tab's `expandedView()` as an overlay on the open shape, with one icon per enabled module in the strip right of the camera housing once there are two or more (D31), followed by a Settings gear (⌘, while the panel is key) that is always shown, even with every module off (D35). `ModuleRegistry.selectedTabID` holds the tab for the session; `selectedModule` falls back to the first enabled module. `NotchRootView` applies the `NotchStyle` margins once around every module's view and wraps it in one VoiceOver group named after the module, so modules don't pad themselves (D37); modules use `NotchEmptyState` for their empty and error states and `NotchSelection` for a selected tab, tile or row. The overlay fades in when the notch opens and is removed at once when it closes (an asymmetric transition: opacity in, identity out), so the text never sits outside the shrinking shape (D19). `settingsView()` has no caller; Settings has its own tabs (D34).

Transient HUDs (timed overlays shown for a few seconds: battery, Bluetooth connect, track change) are a registry feature: a module asks for a timed peek, and the hover state machine shows it. Atoll uses the same idea for its HUDs [V: research/atoll-system-shell.md A2].

## 4. State management

- Models are `@Observable` classes on the main actor (Observation framework, macOS 14+ [V: https://developer.apple.com/documentation/observation/observable]; matches the 14.0 target [V: project.yml]). SwiftUI views update only for the observable properties their body reads [V: https://developer.apple.com/documentation/swiftui/migrating-from-the-observable-object-protocol-to-the-observable-macro].
- One model per module (for example `NowPlayingModel`, `TrayStore`) plus one `NotchState` for the hover state machine and layout.
- Services expose `AsyncStream`s or async functions (CLAUDE.md). A module consumes a stream inside a `Task` it starts in `start()` and cancels in `stop()`.
- The hover state machine (`closed → peek → open`) is a plain value type, `NotchHoverStateMachine`, so it can be unit-tested without a window. Its `handle(_:)` updates the phase and returns which timer to start or cancel; `NotchState` owns the two timers (open delay, exit debounce), not the views (D18).
- **Peek** is the phase while the 0.12 s open delay runs, and through the exit debounce after a brief exit. The shape grows (12 pt each side, 8 pt down) so the user sees the notch has noticed them and the pointer has a bigger target to stay inside. Timed HUDs (section 3) will reuse it later.

## 5. Persistence

| Data | Where | Format | Notes |
|---|---|---|---|
| Settings, module enabled flags, layout | `UserDefaults` via `@AppStorage`/a small settings model | Property list | Small values only. |
| Quick notes | `~/Library/Application Support/DropNotch/Notes/note.txt` | One plain-text UTF-8 file (one note in the MVP, D31) | Human-readable, easy to back up. Saves are debounced (section 9), atomic, and flushed on quit. A file that can't be read is never overwritten. Not through a `FileLocations` helper yet: the module takes the file URL, which tests set. |
| File tray items | `…/Application Support/DropNotch/tray.json`; copies in `…/DropNotch/Tray/<UUID>/<name>` | JSON (`Codable`), atomic write on every change | Holds plain bookmarks, or the folder of a fallback copy (D6, D32). A file that can't be read is never overwritten. |
| Clipboard history | Memory by default; optional `…/Application Support/DropNotch/clipboard.json` (D34) | JSON array of text and link strings, 0600, excluded from backups; images stay in memory | Persistence is off by default (D7). Nothing goes to `UserDefaults`, because Atoll's use of it puts clipboard text in a preferences plist [V: research note §3]. |

No Core Data or SwiftData: the data is small, and plain files are easier to inspect and test. Each module takes its file URL in its initialiser, so tests can point it at a temporary directory.

## 6. Notch panel window

Configuration (all public AppKit; Atoll uses the same flags [V: research/atoll-system-shell.md B1]):
- `NSPanel` subclass, style mask borderless + `nonactivatingPanel`, which Apple defines as a panel that doesn't activate the owning app [V: https://developer.apple.com/documentation/appkit/nswindow/stylemask-swift.struct/nonactivatingpanel]. Whether a click still takes focus is a device check.
- Transparent: not opaque, clear background, no shadow, not movable, `hidesOnDeactivate = false`.
- Level: `.statusBar`, one above the main-menu level, so the panel draws over the menu bar (D16; Atoll uses main-menu + 3 [V]).
- Collection behaviour: can join all Spaces, full-screen auxiliary, stationary, ignores window cycling [V: same flags in Atoll].
- Hosts SwiftUI through a small `NSHostingView` subclass with `sizingOptions = []`, placed inside a plain `NSView` container that is the panel's `contentView`, so the frames come from `NotchGeometry` only. As the `contentView` itself, the hosting view would resize the window to its content (D16). The panel reaches 1 pt above the screen so the top pixel row counts as inside (D20). The hosting view keeps the open panel frame's size (the open shape plus its shoulders, `panelFrame(for: .open)`) and sits top-centred in the clipping container, so the panel grows and shrinks around it without SwiftUI re-laying out the shape (D19). The subclass overrides `acceptsFirstMouse(for:)` to return true, so one click on a control works without activating the window first. (In AppKit, the first click on an inactive window normally only activates it.) [V: Atoll does the same]
- Becomes key only while the hotkey holds the notch open (D30), or after a click in the note or the clipboard search field (D31, D33); hover alone never takes keyboard focus (D16). Closing hands key focus back to the app in front.
- App runs as an agent app (`LSUIElement`), set in project.yml [V: https://developer.apple.com/documentation/bundleresources/information-property-list/lsuielement].

Closed-state hit testing (**D5, accepted**). A window with `ignoresMouseEvents` set is transparent to mouse events [V: https://developer.apple.com/documentation/appkit/nswindow/ignoresmouseevents], so hover can't be detected from it. So the closed panel is resized to exactly the notch rectangle (Atoll does the same [V]) and keeps receiving mouse events. A tracking area on it gives hover enter and exit. Everything outside that rectangle is click-through because the window doesn't cover it. On a notched display there is no menu-bar content behind the notch [I: device check; not in Apple docs]. On a non-notch screen the pill blocks clicks only inside its own small rectangle. Whenever the shape is wider than the closed notch (wings, peek, open), the panel also covers its shoulders, so the transparent corners beside each one (at most 10 × 10 pt) take clicks meant for the menu bar (D36). Rejected: a full-width click-through panel plus a global mouse-moved monitor, which receives a copy of every mouse event sent to other apps [V: https://developer.apple.com/documentation/appkit/nsevent/addglobalmonitorforevents(matching:handler:)], so DropNotch would process pointer movement system-wide.

## 7. Notch vs non-notch and external displays

- Notch present when `NSScreen.safeAreaInsets.top > 0` and both auxiliary top areas exist [V: https://developer.apple.com/documentation/appkit/nsscreen/auxiliarytopleftarea-uglc]. Notch width = screen width minus `auxiliaryTopLeftArea` and `auxiliaryTopRightArea` widths. Height = top inset [V: Atoll's geometry; APIs are macOS 12+ [I]].
- No notch: draw a pill centred at the top. Height defaults to the menu-bar height (full frame minus visible frame) [V: Atoll offers a mode that uses the menu-bar height].
- Frames are rounded to whole pixels for the screen's backing scale, because the top inset can be fractional (33.5 pt) [V: Atoll comment].
- Display choice for MVP (**D9**, implemented by **D17**): one panel on the first screen with a notch, otherwise on the menu-bar screen. All-displays mode is v0.2.
- Displays are identified by `CGDirectDisplayID` from the screen's device description, never by localised name. Atoll's use of names can confuse two identical monitors [V: research note B5].
- `NSApplication.didChangeScreenParametersNotification` triggers a reposition, debounced 200 ms as a design choice (Apple doesn't document bursts) [V: https://developer.apple.com/documentation/appkit/nsapplication/didchangescreenparametersnotification]. Space changes need no handling for the public collection behaviour [I: device check]; `NSWorkspace.activeSpaceDidChangeNotification` exists if needed [V: https://developer.apple.com/documentation/appkit/nsworkspace/activespacedidchangenotification].
- Geometry is computed by a pure value type `NotchGeometry(screenFrame:safeAreaTop:auxLeftWidth:auxRightWidth:menuBarHeight:backingScale:)`, so it is unit-testable without real screens. It outputs `hasNotch`, `closedFrame`, `peekFrame` and `openFrame` (at least the housing plus `topRowWidth` each side on a notched screen, with `openTopRowLeading` where the strip right of the housing begins, D35), and the compact-slot variants `compactFrame` and `compactPeekFrame` (the closed shape plus a square wing each side, D28), all aligned to whole pixels. `menuBarHeight` sizes the pill; when it is 0 (menu bar auto-hidden), a fixed fallback height is used.
- `frame(for:wings:)` is the shape's body for a phase. With wings, the compact frames lose the wing on each side not in `wings`, so a one-sided shape is not centred on the notch; `NotchRootView` offsets it by the difference of the midpoints (D36).
- `NotchShape` draws the body with a flat top, rounded bottom corners and an inverse-curve shoulder each side where it meets the menu bar. `shoulder(for:wings:)` gives the radius: 0 for the plain closed shape (it sits inside the hardware notch), 6 pt compact and peek, 10 pt open. `panelFrame(for:wings:)` is the body plus a shoulder either side and the 1 pt `topOverhang` (D29); the panel, and so the hover and click area, uses it (D36).
- The display choice is the pure `ScreenObserver.chooseDisplay` (D17).

## 8. Module-specific design notes (MVP)

- **Now Playing (D2):** MVP providers are Apple Music and Spotify. Each listens to its player's distributed notification (event-driven) and sends commands with raw Apple Events (D22), which needs one Automation prompt per player, on the first click on a control (D23) [V: Atoll's technique; prompt timing I]. A silent permission check at start never prompts (D23). Sending an Apple Event to a player that isn't running launches it, so commands are sent only to a running player (`NSRunningApplication`), addressed to its pid, and the pid is re-checked just before each send (D22) [I: security-auditor note; device check 4, TASK.md Phase 3]. The progress bar (D26) extrapolates from a position anchor (seconds at a time, rate fixed at 1), never polled; Core Animation draws the motion. Spotify artwork is the one network request (D25); Music artwork is read by Apple Event (D26). MediaRemote is a v0.2 optional provider behind the same protocol.
- **File tray (D32):** `NotchHostingView` is the AppKit drag destination in every state, so dragging a file onto the closed notch peeks, opens it and switches to the Tray tab. Items are stored per D6; bookmarks are resolved when the tray is shown. Drops are `.copy` or `.link` and drags out `.copy` only, so originals never move. AirDrop through `NSSharingService(named: .sendViaAirDrop)` [V: public API used by Atoll], Share through `NSSharingServicePicker` shown below the Share button by `TrayShareMenu`, so a key press can open it too (`ShareLink` has no callable action, D40). Tiles and actions are focus stops (the `keyboardControl` modifier in `Notch/NotchKeyboardControl.swift`); Tab and the arrows step through them and the hotkey focuses the first tile (D40). Thumbnails: not yet (type icons).
- **Clipboard history:** `ClipboardModule` reads `NSPasteboard.general.changeCount` on a timer (section 9, D33). Content is read only when the count changes [V: Atoll does the same]. Items whose types include the concealed or transient markers (`org.nspasteboard.ConcealedType`, `org.nspasteboard.TransientType`, `org.nspasteboard.AutoGeneratedType`) are skipped [I: nspasteboard.org convention; Apple defines no concealed or transient type, https://developer.apple.com/documentation/appkit/nspasteboard/pasteboardtype]. From macOS 15.4 the general pasteboard asks the user on programmatic access [V: https://developer.apple.com/documentation/appkit/nspasteboard/accessbehavior-swift.enum]; see RISKS.md §2 and the D7 probe. Content is never logged. Re-copy writes to the pasteboard; the user pastes. Turn On, Add Clipboard and Clear are focus stops after Search; the hotkey focuses Turn On while history is off, Search otherwise (D40).
- **Quick notes (D31):** one plain-text note in a `TextEditor` in its own tab, saved 1 s after the last edit. ⌃⌥N on the Notes tab puts the cursor in the note; a click in a hover-opened note takes keyboard focus the same way. Escape closes from the note too (the panel catches it in `sendEvent`).
- **Layout (D8):** Settings chooses which module fills the compact-left and compact-right slots and the order of tabs in the expanded view.

## 9. Energy budget

Target: zero wake-ups while idle, apart from the clipboard poll. Intervals below are starting values, to be tuned on a real Mac; unlike Atoll's always-on loops, every repeating timer here runs only while its view is visible or its feature is in use. The performance-optimizer agent checks this before each release.

### Event-driven (no timers)

| What | Event source |
|---|---|
| Hover open/close | AppKit tracking area enter/exit on the notch panel |
| Screen changes | `didChangeScreenParametersNotification` (+ 200 ms one-shot debounce) |
| Now playing (Music, Spotify) | The player's distributed notification on track or state change [V: probe, docs/research/now-playing-probe-2026-10-25.md]; `NSWorkspace` launch and quit notifications. Adds no timers (D24) |
| File tray | Drag-and-drop callbacks |
| Notes | Text-change callbacks |
| Settings | `UserDefaults`/Observation changes |
| Screen sleep, lock, wake | `NSWorkspace` screens-did-sleep/wake notifications [V: https://developer.apple.com/documentation/appkit/nsworkspace/screensdidsleepnotification]; they close the notch, which removes its open content (D19) and so stops the progress animation, and pause the clipboard poll (D33). No screen-lock notification is in Apple's NSWorkspace reference; the documented session notifications cover user switching [V: https://developer.apple.com/documentation/appkit/nsworkspace/sessiondidresignactivenotification], so the MVP pauses on screen sleep only |
| v0.2: battery | IOKit power-source run-loop source [V] |
| v0.2: Bluetooth connect | IOBluetooth connect/disconnect registration [V: documented API exists; Atoll doesn't use it] |
| v0.2: calendar | EventKit store-changed notification [V] |

### Timers that genuinely need to exist

| Timer | Interval | Runs when | Why it can't be an event |
|---|---|---|---|
| Clipboard `changeCount` poll | 0.5 s, tolerance 0.25 s (D7) | Clipboard module enabled, history turned on in the tab, access not Always Deny, and screens awake (D33) | The `changeCount` page describes only the counter; no change notification is documented [V: https://developer.apple.com/documentation/appkit/nspasteboard/changecount]. Reading one integer per tick is cheap [I: not measured]. Atoll uses 0.5 s [V]. |
| Hover open delay | One-shot 0.12 s | Pointer enters the closed notch | Avoids opening when the pointer just passes through. Atoll's default is 0.3 s [V]; that felt slow on the device (D18). |
| Hover exit debounce | One-shot 0.1 s | Pointer leaves | Avoids flicker at the edge [V: Atoll uses 100 ms]. |
| Sweep guard (not a timer) | Per mouse-moved event | Pointer inside the panel only, via the tracking area's `.mouseMoved` | Restarts the open delay above 600 pt/s sideways (D20). No events while the pointer is outside the panel. For about 0.25 s after a close starts the panel is still large (D19), so mouse-moved events reach the guard then; this is the D19 trade-off, and the guard only acts during peek. |
| Play/pause settle | One-shot 1 s | After a play/pause click the player accepted, until an update confirms it | A command that changed nothing sends no notification, so nothing else would undo the optimistic icon (D27). |
| Artwork hold | One-shot 2 s | A track change while the last track's artwork is showing, until the new artwork or its absence arrives | A failed read reports neither, so without it the old picture would stay on the new track (D27). |
| Peek dismissal | One-shot, 2–3 s | A peek HUD is showing | Timed by definition. |
| Screen-change debounce | One-shot 0.2 s | Display change burst | Coalesces bursts. |
| Notes autosave (D31) | One-shot 1 s after the last edit | Typing in the note | Batches disk writes: one atomic write per pause in typing, none while idle. The write is on the main thread (a few KB). |
| Now-playing progress bar (D26) | No app timer: one Core Animation animation per update, capped at 10 fps with `preferredFrameRateRange` | Open notch **and** playing | Progress is extrapolated from the last anchor and the render server draws the motion: 0 app wake-ups [V: harness, 2026-10-25]. Uncapped it redrew at the display rate and added about 12 points of WindowServer CPU; at 10 fps about 3 [V: harness, 60 Hz display]. The bar moves about 2 px/s on a 3-minute track [I: device check 22]. Fallback if it misbehaves: `TimelineView` at 1 Hz. |
| Now-playing elapsed time (D26) | None since D42: the Now Playing card has no time text, so nothing ticks once a second | – | Removed with the v0.2 card; VoiceOver still reads the position on demand. |
| Compact-slot grace (D28) | One-shot 2 s | Playback paused or stopped while the wings show, until it plays again | Keeps the closed shape from flapping on a quick pause or a Music burst, without keeping the menu bar blocked while paused. |
| Decorative waveform (D28) | No app timer: Core Animation repeating animations, capped at 15 fps | Compact view visible **and** playing **and** display awake **and** not Low Power Mode **and** not Reduce Motion | Animation; the render server draws it, as the progress bar. Still bars otherwise. |

The Now Playing source adds no timers and no polling; the open view adds the two rows above (D26). Music's bursts of two states are not debounced; a one-shot 150 ms debounce would be added here only if device check 10 shows a flicker (D24).

Not allowed: any repeating timer while idle, a hover polling loop, a memory watchdog, a Bluetooth poll. These are the loops Atoll runs that we avoid [V: research/atoll-system-shell.md B12].

## 10. Logging and privacy

- `os.Logger(subsystem: "com.shashwat.DropNotch", category: "<Module>")` [V: CLAUDE.md]. Never log clipboard content, file names or track info. Dynamic strings and objects are redacted by default, but integers, floats and booleans are not [V: https://developer.apple.com/documentation/os/generating-log-messages-from-your-code], so mark anything sensitive `privacy: .private` explicitly.
- One network request in the MVP: Spotify artwork, one HTTPS GET per track to `i.scdn.co` only, ephemeral session, no cookies or disk cache, never logged (D25). Lyrics, weather and updates are later features, and each one comes with privacy copy that says what it sends.
- Each permission is requested when its feature is first enabled, never at launch. Now Playing is on by default (D21), so its Automation prompt comes on the first click on a control (D23).
